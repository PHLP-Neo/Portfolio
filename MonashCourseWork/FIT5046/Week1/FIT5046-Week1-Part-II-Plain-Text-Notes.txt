Distributed Computing
A computing paradigm where a number of autonomous
entities (most likely heterogeneous)
which are geographically distributed
can communicate and exchange messages
through a computer network
to achieve certain related tasks (common goals)

========================================================================
SLIDE 4
========================================================================
Distributed Computing Models
The client/server model
-
Servers offer services to clients, and clients request services
-
Usually there is a data storage at the backend (server side)
-
At the front end, a client can be an Android app
Peer-to-peer
-
A decentralised system
-
Each node logically equal to each other
-
Each node can act as a client or a server

[Client-Server Model, so this is a frontend course]

SLIDE 9
========================================================================
Web Apps
-
Web Apps are usually built with HTML, CSS and
JavaScript
-
Accessed via a browser
-
Cross-platform
-
No need for installation
-
Lack of access to device features (e.g. sensors or
camera)
-
Lack of offline operation
-
Low performance (in terms of speed and responsiveness)

========================================================================
SLIDE 10
========================================================================
Native Apps
-
Written in a native language like Kotlin or Swift
-
Distributed through native app stores (Apple App
Store or Google Play)
-
Requires installation on the device
-
It is limited to a specific mobile platform
-
Provides full access to all the features and
hardware of the device
-
High performance
-
Built-in security layers
-
Offline operation capability
Delir Haghighi, P., Perera, A., Indrawan-Santiago, M., & Huynh, T. M. (2014,
November). Situation-aware mobile health monitoring. In 11th International Conference
on Mobile and Ubiquitous Systems: Computing, Networking and Services.

========================================================================
SLIDE 11
========================================================================
Hybrid Apps
-
Hybrid apps combine the benefits of both web
technologies (like HTML, CSS, and JavaScript) with the
capabilities of native apps
-
Supports multiple platforms via a single codebase (but
requires platform-specific adjustments)
-
Limited access to advanced device features
-
Good performance (not quite as high as native apps)
-
Examples: React Native and Ionic
https://ionicframework.com/
Source: https://ionicframework.com/
Sitoula, P., Rahayu, D., Delir Haghighi, P., Goodwin, S., & Ling, C. (2019). Context-
aware smart energy recommender (caser). In Proceedings of the 17th International
Conference on Advances in Mobile Computing & Multimedia (pp. 13-19).

SLIDE 12
========================================================================
Progressive Web App (PWA)
-
PWA apps extend the capabilities of hybrid apps
-
Native-like capabilities and performance
-
Platform-independent
-
Offline capabilities (by caching files locally)
-
Limited access to advanced device features
-
They highly rely on the capabilities of modern browsers
-
Installation optional
https://web.dev/explore/progressive-web-apps

(FIT5046 Guest Lecturer 2022)

Android Jetpack
-
Jetpack includes a large set of libraries for developing high quality apps
https://developer.android.com/jetpack

SLIDE 20
========================================================================
Gradle Build File Types
-
Gradle files simplify importing and using external
repositories.
-
A repository is where external libraries and JAR files are
stored.
-
Dependencies, or external libraries, can be included from
a repository.
-
Once a repository is configured, you can add
dependencies from that repository to your project.
-
Gradle Version Catalogs were introduced to centralise
the management of dependency and plugin versions,
rather than hardcoding versions throughout the build
scripts.
-
The settings.gradle.kts file defines repository locations
https://developer.android.com/build#build-files
https://developer.android.com/build/migrate-to-catalogs

========================================================================
SLIDE 21
========================================================================
Gradle Build Files
-
build.gradle.kts (Project: APPLICATION_NAME)
-
defines the default plugins for building the Android app
-
build.gradle.kts (Module: app): includes dependencies and
configuration settings for this module
-
settings.gradle.kts: includes repositories
-
Google's repository
-
Maven central repository
-
libs.versions.toml: is used to implement library catalog
declarations and includes [versions], [libraries] and [plugins]
https://developer.android.com/build#build-files
https://developer.android.com/build/migrate-to-catalogs

Android SDK Settings
-
The minSdk specifies the lowest version that
app will support but using a very low version
might cause a compatibility issue
-
The compileSdk determines which version of
Android and Java APIs are used for compiling
the code.
-
The targetSdk refers to the version you target
to run the application on it
-
The targetSdk must be equal (or less than) to
compileSdk

Activity Lifecycle
-
onCreate(): must be implemented, and initialise
the activity components (within setContent())
-
OnStart(): the activity becomes visible
-
onResume(): the activity is ready to accept the
user input
-
onPause(): the activity loses focus, and will enter
the stopped or resumed state
-
onStop(): the activity is no longer visible
-
onDestroy(): the activity is about to be terminated
https://developer.android.com/guide/components/activities/activity-lifecycle

[We are only interested in onCreate()]

SLIDE 33

Evolution of Material Design
Material Design 1 (M1)
Introduced in 2014. Established the
foundational principles, visual
language and design philosophy. It is
now archived.
Material Design 2 (M2)
Launched in 2018. Refined the
visual system and introduced more
flexible theming, along with improved
component implementation and code
support.
Material Design 3 (M3)
Launched in 2021. Also known as
Material 3 or Material You. It
introduced dynamic colour, enhanced
personalisation, updated components,
and improved accessibility features.
